## 双轨 API 设计

Flowmail 的每一个业务能力都通过**两个并行 API 层**暴露，共享同一套核心逻辑：

### oRPC — 给人用

oRPC 层驱动 Web 控制台，提供：

- 使用 Zod 验证的类型安全 RPC 过程
- TanStack Query 客户端缓存集成
- 基于 better-auth 的 Session 认证
- 乐观更新，响应迅速

```
浏览器 -> TanStack Query -> oRPC Client -> /api/orpc/[...path] -> 核心逻辑 -> 数据库
```

### MCP — 给 Agent 用

MCP 层提供 AI Agent 访问能力：

- 标准 MCP 协议（兼容 Claude、Cursor、GPT、OpenClaw）
- Bearer Token 认证
- 组织级数据隔离
- 为 LLM 优化的结构化 JSON 响应

```
AI Agent -> MCP Client -> /mcp/[transport] -> 核心逻辑 -> 数据库
```

### 为什么要两个层？

| 关注点 | oRPC | MCP |
|--------|------|-----|
| 认证方式 | Session Cookie (better-auth) | Bearer API Token |
| 消费者 | React 组件 | AI Agent |
| 响应格式 | TypeScript 类型 | JSON 文本（LLM 友好） |
| 实时性 | TanStack Query 轮询 | SSE 流式传输 |
| 可发现性 | TypeScript 类型提示 | MCP Tool 列表 |

核心不变式：**业务逻辑只放在 `packages/` 中**，永远不在 API 层内。oRPC procedure 和 MCP tool 都是调用同一底层函数的薄封装。

## 数据模型

### 核心实体

```
FlowEntity（业务事项）
├── id, type, title, status
├── organizationId（租户隔离）
├── extractedFields（AI 结构化数据）
├── aiSummary
├── assigneeId -> User
├── threads[] -> EmailThread
└── timeline[] -> TimelineEvent
```

### 实体类型与状态机

**审批 (Approval)：**
```
pending -> approved
pending -> rejected
pending -> cancelled
```

**汇报 (Report)：**
```
received -> in_progress -> completed
received -> in_progress -> overdue
```

## 安全模型

### 多租户隔离

所有数据查询都按 `organizationId` 进行隔离：

- **数据库层** — 每条查询都包含 `WHERE organizationId = ?`
- **API 层** — oRPC 从 Session 读取组织；MCP 从 Token 读取组织
- **校验层** — `assertOrgOwns()` 守卫防止跨租户访问

### 邮件安全

| 层级 | 保护措施 |
|------|---------|
| **传输层** | OAuth 2.0 邮箱授权（永不存储密码） |
| **存储层** | 邮件正文静态加密 (AES-256-GCM) |
| **访问层** | 邮件数据仅在所属组织内可访问 |
| **审计层** | 所有访问记录在时间线事件中 |

### 合规性

Flowmail 的设计符合 GDPR 和 CCPA 合规要求：

- **数据最小化** — 仅处理分类所需的邮件元数据和文本
- **删除权** — 支持按用户或组织完整清除数据
- **同意追踪** — OAuth 连接需要用户明确授权
- **审计追踪** — 完整记录所有数据访问和修改的时间线
- **数据可携带** — 支持以标准 JSON 格式导出实体和时间线

## AI 管线

邮件处理管线作为异步任务运行（trigger.dev）：

```
收到邮件（推送通知）
  |
  |-- 1. 解析邮件（主题、正文、发件人、附件）
  |
  |-- 2. 分类（AI：审批 / 汇报 / 问题 / 反馈）
  |      多模型采样计算置信度
  |
  |-- 3. 字段抽取（AI：从邮件正文提取结构化数据）
  |      基于 Zod Schema 的结构化输出
  |
  |-- 4. 关联实体（新建或追加到已有实体）
  |
  └── 5. 生成摘要（AI：为时间线生成简要描述）
```

### 基于置信度的处理策略

- **高置信度（大于 0.85）：** 自动分类并抽取
- **中置信度（0.6 至 0.85）：** 分类但标记需人工复核
- **低置信度（小于 0.6）：** 读取完整邮件正文重新分析
