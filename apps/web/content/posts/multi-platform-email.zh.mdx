## 多平台的现实

以下场景每天在成千上万的公司中上演：

- 你的**总部**使用 Google Workspace（Gmail）
- 你的**美国客户**使用 Microsoft 365（Outlook）
- 你的**中国团队**通过飞书（Lark）沟通
- 你的**自由职业者**使用个人 IMAP 邮箱

每个人都互相发邮件，但每个人都活在自己的邮箱孤岛里。没有一个地方能看到横跨所有平台的项目全貌。

## 为什么这是个问题

### 1. 信息碎片化

当审批、汇报和更新散落在 4 个不同的邮箱平台上时，没有人拥有完整的可见性。项目经理必须检查多个收件箱——或者更糟，依赖他人转发相关邮件。

### 2. 上下文缺失

Gmail 中的线程 A 引用了 Outlook 中的线程 B。但你只能看到线程 A。你在信息不完整的情况下做决策。

### 3. 平台特有的限制

每个平台有不同的能力：
- Gmail 搜索强大但组织功能有限
- Outlook 规则强大但界面复杂
- 飞书与中国商业工具集成良好但与西方平台隔离
- IMAP 客户端的功能和可靠性参差不齐

### 4. 合规复杂性

如果你的邮件数据分布在 4 个不同管辖区的 4 个不同提供商中，证明 GDPR 或 CCPA 合规会变得显著困难。

## 解决方案：一个业务层，多个平台

Flowmail 通过安全的 OAuth 和 IMAP 协议连接所有主流邮箱平台：

| 平台 | 连接方式 | 特性 |
|------|---------|------|
| **Gmail** | OAuth 2.0 + 推送通知 | 实时同步，完整 API |
| **Microsoft 365 / Outlook** | Microsoft OAuth + Graph API | 日历集成，组织级访问 |
| **飞书 / Lark** | OAuth 2.0 + 事件订阅 | 原生中国商业工具支持 |
| **QQ 邮箱** | IMAP/SMTP | 中国广泛的消费者/中小企业覆盖 |
| **163 邮箱（网易）** | IMAP/SMTP | 中国企业邮箱 |
| **任何 IMAP 服务器** | IMAP/SMTP | 通用兼容 |

一旦连接，Flowmail 平等对待所有邮件——无论它们来自哪个平台。Gmail 用户的审批请求和 Outlook 用户的审批请求看起来完全一样。

## 工作流程

### 第一步：连接你的账户

在 Flowmail 设置中，点击"添加连接"并选择平台。OAuth 平台（Gmail、Outlook、飞书）会跳转到授权页面。IMAP 需要输入服务器信息。

所有凭证使用 **AES-256-GCM** 加密，绝不以明文存储。

### 第二步：同步邮件

Flowmail 拉取你的近期邮件并开始分类。新邮件通过推送通知（Gmail、飞书）或定期轮询（IMAP）自动同步。

### 第三步：一个地方看到一切

你的智能收件箱展示来自所有连接账户的邮件，按业务意图组织——而不是按它们来自哪个邮箱平台。

## 真实案例：跨境项目

一家中国科技公司与美国客户合作：

1. **飞书**：内部团队用中文讨论项目
2. **Gmail**：项目经理用英文与美国客户沟通
3. **Outlook**：美国客户的法务团队发送合同修改

没有 Flowmail，项目经理要在三个应用间疲于切换。有了 Flowmail：

- 所有审批请求在一个审批看板中浮现
- 双方的周报自动结构化为统一时间线
- 截止日期提醒不受原始邮件来自哪个平台的影响

## 跨平台安全

连接多个邮箱账户会引起合理的安全顾虑。Flowmail 的处理方式：

- **OAuth 令牌**使用 AES-256-GCM 静态加密
- **每个连接都有限定范围**——Flowmail 只请求所需的最低权限
- **随时可以撤销**连接
- **审计日志追踪**每个连接的同步、发送和访问事件
- **数据留在你的组织内**——无跨租户数据共享

## 开始使用

连接第一个邮箱账户只需大约 30 秒。大多数团队从主要的业务邮箱（通常是 Gmail 或 Outlook）开始，然后根据需要添加其他平台。

目标不是取代这些平台——而是给你一个跨越所有平台的统一业务层。
